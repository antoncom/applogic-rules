## Что это?

Applogic - это библиотека для OpenWrt, позволяющая реализовать логику выполнения программы путём написания пользовательских сценариев, или правил на языке скиптов Lua.

## Область применения

Автоматизация процессов телекоммуникационного оборудования под управлением встраиваемых систем на базе Linux / OpenWrt.

## Варианты использования

* Опрос и управление датчиками
* Опрос и управление модемами сотовой связи
* Приём-передача данных по различным сетевым протоколам
* Преобразование данных
* Предоставление данных в системы мониторинга наблюдаемых величин
* Журналирование и информирование пользователя
* Выполнение управляющих команд

## Преимущества

Попробуйте собрать и обработать 50-100 величин из различных источников в режиме реального времени. Проанализировать их значения, и на основе этого принять решение о поведении системы.
Для этого потребовалось бы написать отдельную программу, отладить её и сопровождать код если источники данных изменятся.

Applogic предлагает не программировать жёстко логику автоматизации, не зашивать код в прошивку при каждом изменении, а описывать эту логику пользоательскими сценариями; редактировать их и отлаживать прямо на устройстве.

При этом пользователю не требуются глубокие знания программирования на языке скриптов, а достаточно иметь базовые знания языка Lua, который считается одним из самых простых.

## Что есть Правило (сценарий)

Правило это шаблонная структура - таблица, состоящая из логических или вычислительных узлов. Узлы связаны в цепочку, т.е. обрабатываются последовательно один за другим.

Узел - это элементарная единица правила. Каждый узел предназначен для обработки какой-то одной величины или технической характеристики прибора. Вычисление осуществляется операторами узла, а результат этого может использоваться следующими узлами в цепочке.

Операторы узла - это универсальные функции, выполнящиеся последовательно в каждом узле. Примеры часто используемых операторов узла:

- [default] - служит для начальной установки значения логического узла;
- [load-ubus] - служит для загузки в узел данных по системной шине UBUS;
- [subscribe] - служит для подписки узла на события системной шины UBUS;
- [timeout] - позволят организовать обратный отсчёт времени, который используется для различных задержек, ожидания данных, событий или действий пользователя;
- [skip] - предназначен для отмены обработки следующих за им операторов по заданному условию. Это экономит вычислительные ресурсы встаиваемой системы, если в определённый момент нет нужды обрабатывать все операторы узла;
- [break] - прерывает обработку всего правила по заданному условию. При этом Applogic переходит к обрабтке следующего правила;
- [journal] - сохраняет текущее, вычисленное значение в БД. Эти же даные могут передаваться в ве-бинтерфейс прибора для отображения журнала событий.
- [websocket] - передаёт результат вычисления узла во внешний мир. С помощью этого удобно реализовать мониторинг в режиме реального времени.
- [frozen] - задерживает вычисленное значение узла на указанное количество секунд.
- [func] - оператор для выполнения произвольного Lua-кода. Это помогает сделать специфичные вычисления преобразования данных, поступающих в узел.

Набор операторов можно расширить, написав собственный оператор.

### Пример описания узла

В следующем примере создадим узел, предназначенный для отслеживания состояния слотов Сим-карт GSM-модема.
Узел содержит 3 оператора:
- [load-ubus] загружает данные о состоянии слотов по системной шине;
- [skip] отменяет следующий за ним оператор, если его выполнение не требуется;
- [journal] добавляет в журнал событий запись о переключении GSM-модема нарезервный слот;


```
slotinfo = {														-- создаём узел, дав ему название
		note = [[ Данные о слотах Сим ]],							-- опрератор [note] хранит краткое пояснение о предназначении узла
		{
			["load-ubus"] = function (nodes)						-- добавляем оператор для загрузки данных по системной шине
				return {
					object = "tsmstm",								-- указываем имя объекта нашине и
					method = "info",								-- вызываемый метод объекта шины
					params = {},
				}													-- В результате в узел "slotinfo" загружаются данные	
			end														-- о состоянии слотов GSM-модема
		},
		{
			["skip"] = function (nodes)								-- создаём узел, отменяющий дальнейшую обработку узла
				local TIME_NOW = os.time()							-- получаем текущее время системы
				local SLOT_TIME = nodes.slotinfo.last_switch_time	-- берём из предыдущего узла время последнего переключения слотов GSM-модема
				loacl WAIT = 10										-- необходимая задержка 10 сек.
				if ((SLOT_TIME - TIME_NOW) < WAIT) then 			
					return false 									-- Если с момента переключения слотов прошло менее 10 сек.,
				else 												-- то есть слот только что переключися на резервную Сим-карту,
					return true 									-- то переходим к следующему узлу
				end
			end
		},
		{
			["journal"] = function (nodes)							-- Создаём узел для журналирования события
				return({
					datetime = os.date("%Y-%m-%d %H:%M:%S"),		-- дата, название события, источник
					name = 'Переключение Sim-слота',				-- и другая вспомогательая информация
					source = "Applogic 01_rule",
					command = "",
					response = ""
				})
			end
		},
	}
```
